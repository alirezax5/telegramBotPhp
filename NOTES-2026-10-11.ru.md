### 1. Методы Managed Bots — живые контракты API (доказаны)
- `request_managed_bot` → `request_id` ОБЯЗАТЕЛЬНО **int**. Строка падает с ошибкой
  `Bad Request: Field "request_id" must be a valid Number` («поле "request_id" должно
  быть числом»). Сохраните объявление типа `int`; задокументируйте его.
- `getManagedBotToken(int $botId)` → возвращает живой токен дочернего бота. На id
  обычного человека возвращает `Bad Request: user is not a bot` («user — не бот»)
  (реальный ответ захвачен).
- Полная живая цепочка доказана: `request_managed_bot` (кнопка клавиатуры,
  request_id=1001) → пользователь подтвердил → обновление `managed_bot`
  `{user: <human>, bot: <child>}` → `getManagedBotToken(bot.id)` → дочерний `getMe` ✔ →
  дочерний `sendMessage` доставлен.
- Также доступны и ошибаются чисто (вживую): `answerChatJoinRequestQuery`,
  `answerGuestQuery` (`QUERY_ID_EMPTY` («пустой query_id»), когда пусто),
  `getBusinessConnection`, `message_thread_id` в приватном чате
  (`message thread not found` («тред сообщения не найден»), пропускается только при
  `has_topics_enabled`).

### 2. Транспорт токена — единственно правильный паттерн (доказано 8/8)
- Токен бота передаётся ТОЛЬКО в пути URL `/bot<token>/METHOD`. Все варианты заголовков
  (Authorization: Bearer, X-Telegram-Bot-Api-Secret-Token, X-Bot-Token, Bot) при
  неверном или отсутствующем токене в пути → 401/404. Токен в query-строке или теле
  JSON → отклоняется. Не добавляйте передачу токена через заголовки.
- Telegram→ваш-вебхук несёт `X-Telegram-Bot-Api-Secret-Token` — это секрет, который ВЫ
  задали в `setWebhook` (ключ маршрутизации на каждого бота), никогда не токен бота.

### 3. Маршрутизация вебхуков нескольких ботов по secret_token (доказано 7/7)
- Два бота, ОДИН файл вебхука, разные `secret_token` — идентичность всегда правильная
  (ветки message и callback_query, реальный трафик). Минимальный пример роутера есть в
  `docs/en/guides/multi-bot.md` (и ещё на 6 языках).
- `webhook.php` для ферм из нескольких ботов: проверяйте
  `X-Telegram-Bot-Api-Secret-Token` через `hash_equals()`, маршрутизируйте на токен
  этого бота из реестра, неизвестным — 403.
