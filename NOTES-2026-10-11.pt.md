### 1. Métodos de Bots gerenciados — contratos da API ao vivo (comprovados)
- `request_managed_bot` → `request_id` DEVE ser **int**. String falha com
  `Bad Request: Field "request_id" must be a valid Number` (PT: "request_id deve ser um número
  válido"). Mantenha a dica de tipo `int`; documente-a.
- `getManagedBotToken(int $botId)` → retorna um token de bot filho ao vivo. Para um id de usuário
  humano, retorna `Bad Request: user is not a bot` (PT: "usuário não é um bot") — resposta real
  capturada.
- Cadeia ao vivo completa comprovada: `request_managed_bot` (botão de teclado, request_id=1001)
  → usuário aceitou → update `managed_bot` `{user: <human>, bot: <child>}` →
  `getManagedBotToken(bot.id)` → `getMe` do filho ✔ → `sendMessage` do filho entregue.
- Também alcançáveis e com erros limpos (ao vivo): `answerChatJoinRequestQuery`,
  `answerGuestQuery` (`QUERY_ID_EMPTY` quando vazio), `getBusinessConnection`, `message_thread_id`
  em chat privado (`message thread not found`, PT: "thread de mensagem não encontrada";
  condicionado a `has_topics_enabled`).

### 2. Transporte do token — o único padrão correto (comprovado 8/8)
- O token do bot viaja APENAS no caminho da URL `/bot<token>/METHOD`. Todas as variantes de
  cabeçalho (Authorization: Bearer, X-Telegram-Bot-Api-Secret-Token, X-Bot-Token, Bot) com um
  token de caminho errado/ausente → 401/404. Token na query string ou no corpo JSON → rejeitado.
  Não adicione transporte de token por cabeçalho.
- Telegram→seu-webhook carrega o `X-Telegram-Bot-Api-Secret-Token` = o segredo QUE VOCÊ definiu
  no `setWebhook` (chave de roteamento por bot), nunca o token do bot.

### 3. Roteamento de webhook multi-bot por secret_token (comprovado 7/7)
- Dois bots, UM arquivo de webhook, `secret_token`s distintos — identidade sempre correta
  (pernas de message + callback_query, tráfego real). O exemplo mínimo de roteador está em
  `docs/en/guides/multi-bot.md` (e em mais 6 idiomas).
- `webhook.php` para fazendas multi-bot: valide o `X-Telegram-Bot-Api-Secret-Token` com
  `hash_equals()`, roteie para o token daquele bot a partir do registro, 403 para desconhecido.
