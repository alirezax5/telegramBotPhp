# Руководство по работе с несколькими ботами

Запуск двух и более ботов внутри одного PHP-процесса — проверка членства в канале с помощью
токена второго бота или разрешение боту №1 отправлять сообщения от имени бота №2.

Поддерживаются два независимых паттерна. Оба были проверены вживую с двумя реальными ботами
(см. [CHANGELOG.md](../../../CHANGELOG.md) — там приведена таблица свидетельств).

---

## Паттерн 1 — Независимые экземпляры

Каждый объект `Telegram` владеет собственным токеном, дескриптором cURL и кэшем апдейтов. Между экземплярами
ничего не разделяется, поэтому изоляция идентичности гарантирована самой конструкцией:

```php
use telegramBotApiPhp\Telegram;

$bot1 = new Telegram($_ENV['BOT1_TOKEN']);
$bot2 = new Telegram($_ENV['BOT2_TOKEN']);

// Scenario A (owner request): membership check executed by bot #2's token,
// from inside bot #1's process.
$member = $bot2->getChatMember('@mychannel', $userId);
if (($member->result->status ?? '') === 'member') {
    // user is in the channel — checked by bot #2
}

$bot1->sendMessage($chatId, 'این پاسخ از ربات ۱ است');
$bot2->sendMessage($chatId, 'این پیام از ربات ۲ است');
```

## Паттерн 2 — Стек токенов на одном экземпляре

Один экземпляр `Telegram` может временно *стать* другим ботом, отправить сообщение и переключиться обратно.
Стек работает по принципу LIFO: каждый `switchToken()` помещает текущий токен в стек, а `restoreToken()`
снимает его.

```php
// Scenario B (owner request): bot #1 sends AS bot #2, inside bot #1's process.
$bot1->switchToken($_ENV['BOT2_TOKEN']);
$bot1->sendMessage($chatId, 'این پیام توسط نمونهٔ ربات ۱، اما با هویت ربات ۲ ارسال شد');
$bot1->restoreToken();

// The same instance is bot #1 again:
$bot1->sendMessage($chatId, 'و این یکی دوباره از ربات ۱ است');
```

Хелперы: `getToken()`, `switchToken(string $token)`, `restoreToken()`,
`clearTokenStack()`, `getTokenStackCount()`.

> Предпочитайте Паттерн 1, когда оба бота используются постоянно — стек рассчитан на
> короткие, чётко ограниченные переключения. Паттерн 2 использует один дескриптор cURL (меньше сокетов),
> Паттерн 1 хранит идентичности постоянно раздельными.

## «Сырые» вызовы

`callRaw(string $method, array $data = [])` выполняет любой метод Bot API и возвращает
**полностью декодированный ответ** (`stdClass` с `ok`, `result`, `description`,
`parameters.retry_after`) — удобно для недавно добавленных методов и для диагностики:

```php
$me    = $bot2->callRaw('getMe');          // $me->result->username
$probe = $bot2->callRaw('getChat', ['chat_id' => '@mychannel']);
```

## Интеграция с фреймворком (TelegramBase)

[Фреймворк TelegramBase](https://github.com/alirezax5/telegramBase) оборачивает эту
библиотеку реестром `BotManager`:

- `BOT_EXTRA_BOTS="second:<token2>,third:<token3>"` (переменная окружения) регистрирует именованных ботов при загрузке;
- плагины получают их через `BotManager::getInstance()->get('second')`;
- сначала нужно проверить `has('name')` — `get()` с неизвестным именем молча откатывается
  к **главному** боту, из-за чего вызов будет выполнен под чужой идентичностью;
- см. `docs/en/multi-bot.md` в репозитории фреймворка.

## Один файл вебхука, много ботов (маршрутизация secret_token)

Вы можете обслуживать **любое количество ботов из ОДНОГО файла вебхука** — без
дополнительных папок, и токены ботов никогда не появляются в URL:

1. Дайте **каждому боту собственный случайный секрет** (`[A-Za-z0-9_-]`, 32+ символов).
2. Зарегистрируйте **один и тот же URL** для каждого бота, каждый со своим секретом:
   `setWebhook?url=https://example.com/hook.php&secret_token=<this-bots-secret>`
3. Telegram возвращает секрет с каждым обновлением в заголовке
   `X-Telegram-Bot-Api-Secret-Token`.
4. В `hook.php` прочитайте заголовок, найдите секрет в реестре
   (`secret → token`), затем создайте соответствующий экземпляр `Telegram`
   (Паттерн 1) и обработайте обновление под этой идентичностью.

```php
// hook.php — весь маршрутизатор в нескольких строках
$registry = [
    'secret-A...' => $_ENV['BOT1_TOKEN'],
    'secret-B...' => $_ENV['BOT2_TOKEN'],
];
$secret = $_SERVER['HTTP_X_TELEGRAM_BOT_API_SECRET_TOKEN'] ?? '';
if (!isset($registry[$secret])) { http_response_code(403); exit; }

$bot = new Telegram($registry[$secret]);           // идентичность этого бота
$update = json_decode(file_get_contents('php://input'), true);
// ... обработайте $update через $bot ...
```

Секрет заодно служит проверкой подлинности (запросы без него исходят не от
Telegram — ответьте `403`). Проверено вживую 2026-10-11: два реальных бота, один файл,
7/7 доставок с правильной идентичностью каждый раз.

Варианты хранения токенов, кратко: фиксированный набор ботов → `.env`; боты,
добавляемые во время выполнения → таблица в БД с колонкой токена, **зашифрованной
при хранении** (кэшируйте поиск); создаваемые пользователями дочерние боты →
управляемые боты (Managed Bots) — токен запрашивается вживую у Telegram через
`getManagedBotToken($user_id)` и никогда не записывается на диск.

## Подводные камни

- **Откат `get()`**: вызов `get('unknown-name')` возвращает главного бота (с
  предупреждением в логе), а не выбрасывает исключение — всегда предварительно проверяйте через `has()`.
- **Стек токенов привязан к экземпляру**: переключение токенов на `$bot1` не влияет на `$bot2`.
- **Несбалансированный restore**: если вы вызвали `switchToken()` без соответствующего `restoreToken()`
  на пути возникновения исключения, экземпляр сохранит заимствованную идентичность. Используйте try/finally:
  ```php
  $bot1->switchToken($t2);
  try {
      $bot1->sendMessage($chatId, 'as bot #2');
  } finally {
      $bot1->restoreToken();
  }
  ```
- **Загрузка файлов внутри JSON-полей**: локальные пути для `stickers`, `media` и т.д.
  автоматически преобразуются в `CURLFile` (v3.3.0+) — но только до JSON-кодирования, поэтому
  для этих параметров всегда передавайте PHP-массивы (а не заранее закодированные JSON-строки).
