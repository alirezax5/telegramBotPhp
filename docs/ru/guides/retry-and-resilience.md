# Повторы и устойчивость

SDK содержит небольшой встроенный слой надёжности HTTP в `Telegram::bot()`.

## Политика повторов

- **Попытки:** до `maxRetries` повторов (по умолчанию **3**) после первого запроса.
- **Триггеры повтора:** ошибка cURL/сети, серверная ошибка `5xx` и `429` (ограничение частоты).
- **Задержка:** экспоненциальная — `retryDelayMs * 2^(attempt-1)` (по умолчанию первая задержка 500ms → 1s → 2s).
- **Учёт 429:** если ответ API содержит `parameters.retry_after`, клиент выжидает ровно это количество **секунд** перед повтором (вместо экспоненциальной догадки). Это позволяет не «долбить» ограничитель частоты.

## Поведение cURL

- Единственный дескриптор cURL создаётся лениво и **переиспользуется** между вызовами (переиспользование соединения при long polling). Освободите его через `close()` или при деструкции.
- `CURLOPT_TIMEOUT` по умолчанию равен 30s (параметр конструктора `$curlTimeout`). Для long-poll `getUpdates` с явным `timeout` тайм-аут сокета поднимается до `timeout + 5`, чтобы медленный long-poll-ответ не был обрезан.
- Проверка SSL включена (`CURLOPT_SSL_VERIFYPEER => true`).

## Форма возврата при сбое

Когда повторы исчерпаны, `bot()` возвращает `stdClass`:

```php
(object)[
    'ok'       => false,
    'error'    => 'curl error message' ?: 'API Error after N attempts',
    'http_code'=> 200|429|5xx|0,
    'attempts' => N,
];
```

`callRaw()` возвращает этот «сырой» объект; типизированные методы заворачивают поле `result`, если оно присутствует.

## На практике

```php
$bot = new Telegram($token, maxRetries: 5, retryDelayMs: 300, curlTimeout: 60);

$res = $bot->sendMessage($chatId, 'Hi');
if (!($res->ok ?? false)) {
    // handle API error via $res->error / $res->http_code
}
```
