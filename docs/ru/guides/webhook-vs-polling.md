# Вебхук или Long Polling

SDK поддерживает оба режима доставки — выбор делается на уровне приложения.

## Вебхук (требуется HTTPS)

```php
$bot = new Telegram($token);
$update = $bot->getInputData();      // decodes php://input

if ($bot->isMessage()) {
    $bot->sendMessage($bot->chatId(), $bot->text());
}
```

- **Плюсы:** работа в реальном времени, никакой нагрузки от поллинга, ни одно соединение не держится открытым.
- **Минусы:** требуется публичный HTTPS-эндпоинт; колбэки логируются Telegram.

### Настройка

```php
$bot->setWebhook('https://example.com/hook');
$bot->getWebhookInfo();
$bot->deleteWebhook();
```

> Примечание: современный формат позволяет передавать `secret_token`, `max_connections`, `allowed_updates` через массив `$options`.

## Long polling (публичный сервер не нужен)

```php
$bot = new Telegram($token);
$offset = 0;

while (true) {
    $updates = $bot->getUpdates($offset, 100, 50);   // offset, limit, longpoll timeout(s)
    foreach ($updates->result as $u) {
        $offset = max($offset, $u->update_id + 1);
        $bot->setInputData($u);
        // ...handle
    }
    usleep(200_000);   // 0.2s
}
```

- **Плюсы:** работает за NAT, TLS не нужен, просто.
- **Минусы:** держит сокет открытым; каждый опрос — это сетевой round-trip.

**Примечание о тайм-ауте long polling:** тайм-аут cURL в SDK по умолчанию составляет 30s, но для `getUpdates` используется тайм-аут, переданный Telegram, а тайм-аут cURL поднимается до `timeout + 5`, чтобы HTTP-запрос не оборвался до того, как Telegram ответит.

### Время жизни / один экземпляр

Для каждого бота должен работать ровно один процесс поллинга. Два процесса, разделяющие смещение `getUpdates`, могут молча расходовать апдейты друг друга (см. отладку проблемы *молчащего бота*). Используйте менеджер процессов (systemd / supervisor), чтобы поддерживать процесс в живом состоянии, а не несколько параллельных процессов.

## Выбор

- Публичные продукты, открытые наружу (Telegram webhook) → **вебхук.
- Локальная/разработка за NAT → **поллинг.
- Общий хостинг, который не может держать процесс открытым → поллинг со скриптом, запускаемым по cron, подходит для низкой частоты, но для объёмов Telegram предпочтителен постоянный процесс.
